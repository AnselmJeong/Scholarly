# 학습 노트·생성 속도·네이티브 전환 검증

2026-11-13, macOS arm64. 이 문서는 실제 측정과 남아 있는 검증을 구분한다. 모델 대조 결과를 사람의 완전한 원문 검토로 표현하지 않는다.

## 제품 결정

기본은 충분히 설명하는 **학습 노트**, 추론 강도는 지원되는 `low`다. 현재 계정 기본 모델 `gpt-6.1-sol`은 `none`을 지원하지 않는다. 지원하지 않는 설정을 몰래 다른 값으로 바꾸지 않는다. 일반 논문은 본문 전체로 한 번 작성하고, 형식·완결성·출처 범위를 검사한 후 `원문 대조 미실행`으로 저장한다. 별도의 원문 대조는 필요할 때 실행한다.

DeepPaperNote의 [README](https://github.com/917Dhj/DeepPaperNote), [figure placement](https://github.com/917Dhj/DeepPaperNote/blob/main/skills/deeppapernote/references/figure-placement.md), [Obsidian format](https://github.com/917Dhj/DeepPaperNote/blob/main/skills/deeppapernote/references/obsidian-format.md)를 참조했다. 조사한 커밋은 `c4d93dc5948a96f27361d30127e42619b8919a17`이다. 실제 기본 산출물은 Markdown·이미지·부속 파일이며, HTML만 저장하는 구조가 아니다. 설명 가까이에 원문 그림을 배치하고, 그림의 축·패널·범례를 확인하며, 개인 메모를 보존하는 원칙을 적용했다. upstream 코드를 복사하거나 그 저장소의 도구를 설치하지 않았다.

모델은 내용만 작성한다. 앱이 같은 내용을 네이티브 읽기 화면과 HTML로 표시한다. HTML 생성에 추가 모델 호출은 없다. 수식과 그림도 로컬 캐시와 원문을 이용한다. 이미지 자체를 읽지 않은 생성 결과에는 이미지 판독을 주장하지 않는다. 그림 자동 선택·완전 자동 크롭은 구현하지 않았다. 현재는 원문에서 드래그한 영역을 선택한 절의 설명 옆에 붙인다. 절 제목이 달라지면 보관한 그림으로 남겨 위치 확인을 요청한다.

## 여섯 논문 평가

모델 `gpt-6.1-sol`, 추론 `low`, 한국어. 첫 본문 시간은 스트림이 200문자에 도달한 시점이다. 네트워크·계정 부하에 따라 달라지므로 보장값이나 p95가 아니다.

| 논문 | PDF 쪽 | 최초 작성 | 첫 본문 | 어절 | 최초 호출 수 |
|---|---:|---:|---:|---:|---:|
| Rusch 2025, 계층 모듈 신경망 | 11 | 138.5초 | 11.6초 | 1,894 | 1 |
| Lappin 2025, 전뇌 모형과 재발 | 18 | 129.8초 | 7.8초 | 2,197 | 1 |

- 원문 텍스트와 캡션을 제공한 별도 AI 대조: 최종 결과 6/6에서 중대한 내용 오류가 보고되지 않았다. 논문별 이해 질문은 29/30을 노트에서 답할 수 있다고 평가했다. Rusch의 추가 네트워크 크기·재연결 통제 질문 1개는 미포함이며, 평가자는 주된 결론을 바꾸는 누락으로 보지 않았다.
- **전부 첫 시도 통과라는 뜻은 아니다.** Menon은 그래프 허브·질환 단계, 의식/발작, 광유전학 관련 주요 논의 누락을 보강했다(추가 작성 135.3초). Brinkman은 연속/이산 HMM 체류시간 구분, 억제 가소성의 필요조건, 내부 추출 메모를 수정했다(185.1초). 해당 결과는 재대조했다.
- 직접 확인한 범위: 위 수정 사항의 원문 근거, Bruining의 지표 정의·DFA 조건·시간창 및 약물 비교 기준, Lappin의 모형/임상 해석 구분. 모든 원문 전체를 사람이 독립적으로 판독한 것은 아니다.
- 평가의 AI 대조·보강 시간은 표의 최초 작성 시간에 **포함되지 않는다**. 기본 학습 노트 경로의 속도와 완전한 대조 포함 시간을 혼동하지 않는다.

이전 concise 프롬프트의 초안만 같은 모델·low로 비교할 수 있는 네 논문에서는 39.4~48.3초, 559~605어절이었다. 새 노트는 더 자세하기 때문에 **초안 완성 자체가 더 빨라졌다고 주장할 수 없다**. 이전 앱의 필수 대조 시간은 이 비교에 들어 있지 않으며, 전체 사용 시간의 개선 배수도 산출하지 않았다. 기본 경로의 호출 수 감소와 스트리밍은 각각 별도 개선이다.

## 빠른 모델과 네이티브 경로

Bruining 원문·같은 학습 프롬프트·low로 `gpt-6-luna`를 3회 실행했다. 84.1 / 84.5 / 87.9초였고 첫 본문은 5.0 / 5.3 / 5.4초였다. 별도 대조에서 1/3만 통과했다. 실패한 두 결과는 투여 후 0–0.5시간 기준 구간을 투여 전 기준으로 잘못 설명하거나, EEG slowing을 활동량 감소처럼 옮겼다. 원문에서 직접 확인했다. 따라서 이 모델을 자동 기본값으로 채택하지 않았다. 사용자는 설정에서 계정 모델을 선택할 수 있다.

Rust 생성 경로로 Bruining을 실제 Codex 계정에서 다시 작성했다: **132.9초, 첫 본문 5.9초, 1,878어절**. 별도 원문 대조는 중대한 오류 없음, 이해 질문 5/5로 평가했다. Rust로 바꾼 것만으로 원격 모델의 생성 시간이 단축된다는 주장은 하지 않는다.

## 데이터와 안전성

기존 DB를 SQLite 온라인 백업으로 별도 네이티브 데이터 폴더로 이관했다. 원본은 수정하지 않았다. 읽기 전용 트랜잭션에서 모든 열을 포함한 정렬된 행의 SHA-256을 비교했다.

| 테이블 | 원본 / 사본 | 전체 행 일치 |
|---|---:|---|
| articles | 2,195 / 2,195 | 예 |
| keywords | 2,128 / 2,128 | 예 |
| article_keywords | 15,995 / 15,995 | 예 |
| chat_sessions | 26 / 26 | 예 |
| chat_messages | 70 / 70 | 예 |

SQLite 무결성 검사 `ok`. ID·경로·메타데이터·표시·관계·대화 순서와 시각까지 비교 대상에 포함했다. 이후 새 앱에서 변경한 데이터는 원본 앱과 자동 동기화하지 않는다.

완료되지 않은 스트림·취소·출처 범위 오류는 게시하지 않는다. 재작성은 기존 노트와 원본의 변경 여부를 다시 확인하고 원자적으로 교체한다. 이전 버전과 누적 이력, 개인 메모, 원문 그림을 보존한다. 원문 또는 본문 해시가 바뀌면 기존 대조 완료 표시를 사용하지 않는다. Codex는 공식 App Server의 구독 계정과 사용 한도를 확인하며, API 과금 경로로 자동 전환하지 않는다. 도구·MCP·웹·셸 실행은 요청에서 비활성화한다.

## 재현과 검증 자료

- `2026-11-13/<kind>/`: 원문 텍스트, 최초 결과, 보강 전 사본, 시간·사용량, 본문 해시에 연결된 AI 대조 결과.

## 원래 UI 복원과 설치 후보

기능 위주로 만든 초기 네이티브 화면은 기존 앱의 세밀한 UI를 충분히 보존하지 못했다. 설치된 Electron 앱을 직접 비교 기준으로 삼아 남색 3단 구조, 키워드/폴더 탐색, 논문 표와 연도 배지, 중요/읽음 표시, 오른쪽 상세 패널, Lapis Dark 읽기 배경을 복원했다. 노트 열기는 표에서 선택과 분리하고, 읽기 도구는 작은 아이콘과 추가 작업 영역으로 정리했다. 탐색 목록도 가상화하고 패널 폭은 저장한다. 원래 키워드에 포함된 쉼표를 분리하지 않도록 배열로 읽고, 편집은 한 줄에 하나씩 입력한다.

`/Volumes/Aquatope/Applications/Scholarly Native.app`에 개발 인증서로 서명한 후보를 별도 설치했다. 원래 앱은 유지한다. 현재 서재 964편·검색·900px 상세 전환·한글 붙여넣기를 확인했으며, HTML에서는 수식 47개와 그림 1개 및 화면 폭에 따른 배치를 확인했다. 자동 검사와 실제 UI 검증은 구분한다. 당시 macOS 외장 볼륨 승인이 필요해 사용자에게 요청했다. 아래 11월 14일 설치본 검사에서 승인이 해제된 뒤 남은 항목을 검증했다.


## 2026-11-14 설치본 UI 검사와 그림 연결 수정

- 사용자 승인 뒤 폴더 선택창을 통해 검증용 실제 논문 6편을 열었다. 원래 서재는 검사 후 복원했다.
- 본문에서 그림이 아래로 밀리는 현상을 재현했다. GPUI 이미지의 백분율 폭과 자동 높이 조합이 원본 PNG 높이를 사용했다. 백그라운드에서 읽은 PNG 비율로 부모 영역을 정하고 이미지가 그 영역을 채우도록 수정했다. 원문 페이지·크롭 표면에도 같은 규칙을 적용했다.
- 절 첫 문단을 무조건 그림 해설로 붙이는 규칙을 제거했다. 캡션의 그림 번호와 같은 절의 명시적 Fig./Figure/그림 인용을 연결하며, 인용이 없는 문단은 순서 그대로 유지한다. Figure 1과 Figure 10의 오연결, 번호 범위, 대응 문단 없는 경우를 기존 회귀 검사에 추가했다. 추가 AI 호출은 없다.
- 실제 Bruining Figure 1과 sE/I 증가에 따른 진폭·LRTC 관계의 해설이 나란히 표시됨을 확인했다. 본문 영역을 좁히면 세로로 이어진다. `.scholarly-eval/native-figure-alignment-fixed.png`에 수식과 수정 배치를 기록했다.
- 블록 수식에서 Markdown 파서가 제거하는 앞뒤 개행과 수식 캐시 키를 일치시켰다. 설치본에서 분수·첨자·합계 및 인라인 수식을 확인했다.
- 한글 입력기에서 개별 `g,k,s,r,m,f` 키로 `한글` 조합을 확인했다. Unicode 일괄 입력이나 붙여넣기 검사와 구분했다. 메모 저장 후 앱 재실행으로 보존을 확인하고 검증 메모는 비웠다.
- 본문을 실제 드래그 선택해 복사한 뒤 메모 칸에 붙여넣어 동일한 한국어 문구를 확인했다.
- 기존 노트를 UI에서 재작성해 새 본문이 나타나는 중에 취소했다. `.scholarly-eval/ui-cancel-baseline.json`과 비교해 기존 노트·manifest·원문 그림 SHA-256이 모두 그대로였다. 완성 생성 경로는 앞의 실제 Rust 계정 실험과 별개로 기록한다.
- 원문 3쪽에서 그림 영역을 드래그해 연결하고, 마지막 연결 해제로 원래 그림 1개 상태로 복구했다.
- 900px 읽기 전환 후 기본 창 복귀에서 서로 다른 구성의 패널 폭이 섞이는 문제도 수정했다. 각 구성에 별도 크기 상태를 유지하고 저장값의 범위를 제한한다.
